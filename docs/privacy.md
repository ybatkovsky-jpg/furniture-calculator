# Политика обработки и хранения ПДн (P2-21)

Документ описывает, где лежат персональные данные клиентов и как с ними
обращаться. Юридические сроки хранения подтверждает собственник/юрист —
здесь зафиксированы технические меры.

## 1. Где ПДн

| Место | Данные | Доступ |
|---|---|---|
| `data/furniture.db`, таблица `projects` | ФИО, телефон, адрес объекта | бот (владелец проекта), администратор БД |
| `pdfs/KP_*.pdf` | КП с именем/адресом клиента | бот (владелец), файловая система |
| `input_images/`, `output/`, `temp/` | сканы/рендеры чертежей, могут содержать штампы с адресом | файловая система |
| `bot_debug.log` | ID пользователей, тексты ошибок; **не должен** содержать ФИО/телефон | файловая система |
| Git-репозиторий | **не должен** содержать ПДн | — |

## 2. Технические меры (сделано)

- `pdfs/`, `data/`, `*.db`, `*.xlsx` (кроме `templates/*.xlsx`) — в `.gitignore`;
  клиентские PDF/XLSX выведены из Git (P0-04).
- `.dockerignore` не пускает `.env`, `data/`, `pdfs/`, `temp/`, `output/` в образ.
- Доступ к админ-командам и прайсу — fail-closed + owner-check (P0-05/P1-14).
- `ALLOWED_TELEGRAM_IDS` ограничивает круг пользователей бота.
- SQLite работает в WAL; бэкапы — `scripts/backup_db.py` (см. `docs/runbook.md`).

## 3. Срок хранения и удаление

Срок хранения ПДн клиентов — **решение собственника** (бухгалтерские/договорные
требования). Технически удаление выполняет скрипт:

```powershell
# dry-run: показать, что будет удалено
.\.venv\Scripts\python.exe scripts\purge_old_projects.py --days 1825

# удаление (только после бэкапа и письменного решения)
.\.venv\Scripts\python.exe scripts\purge_old_projects.py --days 1825 --apply
```

Скрипт удаляет проекты старше срока вместе с расчётами и КП-записями. Файлы
`pdfs/KP_*` и сканы автоматически не удаляются — их удаляют отдельно, вручную,
после сверки.

## 4. Логи

- В логи не пишем токены, ключи, ФИО, телефоны, адреса.
- `bot_debug.log` ротируется (10 МБ × 3); при передаче логов поддержке —
  вычищать ID пользователей.
- При инциденте: остановить бота, сохранить копию, оценить обязанность
  уведомления регулятора (152-ФЗ), уведомить ответственного за ПДн.

## 5. Что осталось

- Шифрование БД и роли доступа (этап 5, PostgreSQL).
- Автоматический retention по расписанию — после утверждения срока.
- Согласие клиента на обработку ПДн и политика на сайте — организационная
  задача (S0-L1).
