# План повышения точности и прогнозируемости распознавания

**Дата:** 19.11.2026
**Цель:** состав мебели, который менеджер только подтверждает, а пропуски видны
и измерены — а не угадываются.

---

## 1. Что считаем успехом (метрики)

Сейчас измеряем «на глаз»: сошлось/не сошлось. Вводим четыре числа.

| Метрика | Что означает | Сейчас | Цель |
|---|---|---|---|
| **Полнота дверей** | найденные / реальные по эталону | 13 из 15 на `0002` (87 %) | ≥ 95 % |
| **Покрытие по ширине** | сумма ширин модулей / габарит с чертежа | не считается | ≥ 95 % |
| **Повторяемость** | разброс цены при повторном прогоне того же листа | до ±27 % | ≤ ±5 % |
| **Пропуск без флага** | страниц, где потеряно >5 % и это не помечено | не измеряется | **0** |

Последняя метрика — главная. Полной полноты не будет, но **молчаливых** пропусков
быть не должно.

## 3. Работы по направлениям

### A. Полнота: заставить модель перечислять

**A1. Нарезка листа (кроп-проходы) — ПРОВЕРЕНО, НЕ ПОДХОДИТ для многоракурсных листов.**
19.11 на `0002` нарезали на 4 квадранта: без перекрытия суммарно **37 дверей**
при истине 15, с перекрытием — 40. Причина: на листе несколько проекций одной
кухни, и каждый фрагмент видит «свою» проекцию как отдельную кухню. Нарезка
годится только для однопроекционных листов; для многоракурсных запрещена.

**A2. Перечисление вместо описания.**
Промпт требует таблицу: «корпус №, ширина, высота, двери, ящики, полки».
Пустая строка сразу заметна, «в целом» не проходит.
*Проверка:* на `0002` должно стать 15 строк-дверей.

**A3. Два прохода — СДЕЛАНО 19.11, объединение отклонено, работает согласие.**
Объединять модули нельзя: проходы группируют по-разному (`2091×786` против
`1870×785` — та же кухня), сумма даёт 28–33 двери вместо 15. Вместо этого
`app/services/two_pass.py`: согласие по дверям, при ≥ 0,90 берём меньшее число,
иначе флаг «нужен переспрос». Проверено на `0002`: проходы 16 и 17 → согласие
0,94–0,97 → решение 16; при расхождении 16 и 12 → флаг.
*Цена:* ×2 вызова.

**A4. Точечный переспрос — СДЕЛАНО 19.11, эффект нестабилен.**
`analyze_page(hint=...)` добавляет уточнение и получает свой ключ кэша.
Проверено: на `0002` принудительный переспрос дал **15 дверей** (истина 15),
но в другом прогоне — 27. На стенде `0001` исправлен (4 → 2), `0011` приближен
(5 → 4), `0002` отклонён правилом приёмки. Правило `accept_reask`: принимаем
только в допуске ±15 % от согласия проходов, иначе остаётся флаг менеджеру.
Вывод: переспрос — диагностика, не автоматическая коррекция.

### B. Проверяемость: пропуск должен быть числом

**B1. Покрытие по ширине в мм.**
`покрытие = сумма(ширин модулей) / габарит_OCR`. Порог 95 %.
Считаем **по зонам** (левая/правая половина), чтобы знать, где искать.

**B2. Покрытие по высоте.**
Сумма высот ярусов против H помещения (мин. 2 400). Расхождение > 300 мм — флаг.

**B3. Правдоподобие состава.**
- двери на метр ширины: 1,5–3,5 (15 дверей на 4,86 м = 3,1 ✓; 15 на 1,6 м = 9,4 ✗);
- модули: ширина 250–1 200, глубина 200–900;
- у нижней базы есть фасад или ящики.

**B4. Confidence считает код, а не модель.**
Модель ставит «high» почти всегда — бесполезно. Считаем из фактов:
совпадение OCR↔модель (вес 0,35), покрытие (0,35), правдоподобие (0,2),
ответ с первой попытки (0,1). Ниже 0,6 — КП блокируется, причина списком.

### C. Повторяемость

**C1. Температура 0** для всех вызовов (сейчас не фиксирована).

**C2. Кэш по версии правил — СДЕЛАНО 19.11.** Сброс: `scripts/cache_clear.py --page 0002`
или `--all`. `analyze_page` теперь читает и пишет
`data/recognition_cache/{sha256 картинки[:16]}_{sha256 промпта[:8]}.json`.
Проверено на `0002`: первый прогон 148 с, повторный **0,9 с**, двери 16 и 16 —
числа совпадают. Осталось: кнопка «сбросить кэш» в админке.

**C3. Метрика согласия двух проходов — ЖДЁТ БЮДЖЕТА.** Разные проходы нужны только
с разными промптами/моделями: при temperature 0 и включённом кэше второй проход даёт
тот же ответ. Требует платных вызовов (routerai сейчас отдаёт 429 «недостаточно средств»).

**C4. Заморозка эталона — СДЕЛАНО 19.11.** `tests/test_album_frozen.py` проверяет
сохранённые ответы: `0002` с покрытием >110 % обязан иметь флаг, `0008` без модулей —
низкую оценку, `0006` при нормальном покрытии — надёжную. Сети нет, тест дешёвый.

### D. Качество входа

**D1. Плотность рендера.** 150 dpi → **200 dpi** для листов с мелкими размерами
(проверить на `0005`, `0007`, где OCR не дал чисел).

**D2. OCR размерных линий.** Проверить наклон/поворот (deskew), увеличить
контраст перед Tesseract.

**D3. Отбраковка входа.** Слишком тёмный/размытый скан → сразу сообщение
«переснимите», не тратить модель.

### E. Модель

**E1. Убрать 8B из цепочки.** Порядок: `deepseek-flash → routerai (Qwen3-VL-235B)`.
8B оставить только для офлайн-прогонов, с явным предупреждением в результате.

**E2. Не менять модель «на всякий случай»** — только по замеру на эталоне.

## 4. Порядок внедрения

| Этап | Работы | Срок | Критерий приёмки |
|---|---|---|---|
| **P0** | Стенд замера: скрипт считает полноту, покрытие, повторяемость по 12 страницам | 1 день | есть отчёт с 4 метриками по каждой странице |
| **P1** | B1–B4: покрытие в мм, зоны, правдоподобие, confidence кодом | 2 дня | на `0002` флаг «не хватает ~1 000 мм», а не тихая смета |
| **P2** | A1–A2: нарезка + перечисление | 3 дня | `0002` даёт 15 дверей |
| **P3** | A3–A4: два прохода и точечный переспрос | 2 дня | полнота ≥ 95 % на альбоме |
| **P4** | C1–C4: temperatura 0, согласие проходов, кэш, эталон | 2 дня | разброс цены ≤ ±5 % на 5 повторах |
| **P5** | D1–D3: 200 dpi, deskew, отбраковка | 1 день | `0005`/`0007` получают OCR-габарит |

Итого ~11 рабочих дней. P0 и P1 дают эффект сразу: даже без улучшения
распознавания пропуски перестанут быть тихими.

## 5. Стоимость

| Сценарий | Вызовов на страницу | Комментарий |
|---|---:|---|
| Сейчас | 1 | базовый |
| + нарезка | 4 | ×4 |
| + два прохода | 8 | ×8 |
| + переспрос (редко) | до 10 | только при недостаче |

Ориентир: прогон альбома (12 страниц) — около 100 вызовов. Точная цена
считается по факту после P2, до этого не обещаю.

## 6. Чего не делаем

- **Не улучшаем промпт по одному прогону.** Уже обжигались: −2,5 % → +26,8 %.
  Любая правка — только с замером на эталоне до/после.
- **Не подставляем цены молча.** Нет цены → «⚠ Проблемы» + блок КП.
- **Не считаем «на глаз» без покрытия.** Смета без покрытия не выпускается.
- **Не тащим 8B как резерв** — даёт половину дверей.

## 7. Что увидит менеджер после внедрения

Вместо «Кухня 4,86 м, 13 дверей, 212 150 ₽»:

```
Кухня, габарит 4 860 мм (OCR)
найдено: 4 740 мм = 97 % ширины, 15 дверей, 6 ящиков
проверка: покрытие 97 % ✓, двери на метр 3,1 ✓
предупреждений нет
```

Если чего-то не хватает:

```
⚠ не найдено 620 мм ширины (правая часть листа)
⚠ дверей 11 при ожидаемых 15 — проверьте фасады
КП заблокировано: состав неполный
```

Второе — и есть главный результат: смета перестаёт быть «правдоподобной»,
она становится **проверенной или помеченной**.
