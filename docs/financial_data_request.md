# Запрос исходных данных для финансовой политики v1.0

**Кому:** бухгалтер, банк, производство, директор  
**От:** финансовый блок / внедрение Furniture Calculator  
**Цель:** закрыть параметры `TaxPolicy`, `PaymentPolicy` и расчётной базы `B`, без которых нельзя утвердить окончательную финансовую модель и выпускать КП.

> До получения данных расчёт имеет статус `provisional`; окончательное КП не выпускается. Наценка `13%` за безнал сохраняется; это не налог.

## 1. Бухгалтер: налоги

**Подтверждено:** УСН «доходы минус расходы», 15%, Хабаровский край; **НДС не применяется**.  
**Осталось подтвердить:**

| № | Что нужно | Зачем | Формат |
|---|---|---|---|
| 1 | Право на пониженную региональную ставку (15% или ниже) | `TaxPolicy.region/regional_rate` | письмо/реквизиты |
| 2 | Минимальный налог 1%: порядок расчёта и зачёта | `Min_tax` | описание |
| 3 | Состав вычитаемых расходов: какие статьи `B`, `D_internal`, `P` принимаются для УСН | `Tax_base` | перечень/письмо |
| 4 | Страховые взносы и иные обязательные платежи, относимые к затратам | состав `B` | ставки/база |
| 5 | Как учитывать комиссии банка/эквайринга в налогах | `PaymentPolicy.vat_treatment` | описание |
| 6 | Ограничения по формам оплаты и договорным формулировкам | чтобы не показать клиенту «комиссию» | письмо |

## 2. Банк / бухгалтер: платежи

| № | Что нужно | Зачем |
|---|---|---|
| 1 | Тариф за банковский перевод | `PaymentPolicy.percent_fee/fixed_fee` |
| 2 | Эквайринг: ставка, фикс, min/max | `PaymentPolicy` |

## 3. Производство / директор: расчётная база

| № | Что нужно | Зачем |

### 3.1. Что показала выгрузка заказов

См. подробный разбор: `docs/order_data_analysis.md`.

По ссылке на «ФИНАНСЫ ПРОМЕБЕЛЬ» (45 строк) на 17.11.2026:

- цена договора заполнена у 40 из 45 заказов;
- «Итого себестоимость» заполнена/ненулевая только у 20 из 45;
- «Фактические затраты» заполнены/ненулевые у 27 из 45;
- у 18 заказов одновременно есть и плановая себестоимость, и фактические затраты;
- в 8 заказах указан бонус дизайнера на сумму 565 830 ₽, но колонка «Прибыль» его не вычитает;
- в 5 заказах фактические затраты больше «Итого себестоимость»;
- в 2 заказах «Фактически получено денег» больше цены договора;
- в 18 заказах фактические затраты равны 0/пусто, поэтому «Прибыль» равна цене договора — это не прибыль, а отсутствие данных.

По 20 заказам с плановой себестоимостью наценка к ней: медиана **42,9%**, среднее **45,6%**, диапазон **21,3–106,2%**; только 7 заказов попали в диапазон 25–35%. По фактическим затратам медиана **71%**, но 13 из 27 заказов имеют наценку >75% — это признак неполных фактических затрат, а не реальной маржи.

**Вывод:** выгрузка не позволяет утвердить коэффициенты `B`. В ней нет разделения на материалы, производство, проектирование, монтаж, накладные, доставку, налоги и комиссии; «Итого себестоимость» и «Фактические затраты» — разные и неполные величины. Для калибровки нужна детализация по 20 заказам.

### 3.2. Формат детализации по 20 заказам

| Заказ | Цена | Материалы | Комплектующие | Производство | Проектирование | Монтаж | Накладные | Доставка внутр. | Налоги | Комиссии | Бонус дизайнера | Факт оплаты |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
|  |  |  |  |  |  |  |  |  |  |  |  |  |

Без этих колонок нельзя отличить «30% на B» от «30% на материалы» и нельзя проверить, какая модель соответствует фактическим ценам.

## 4. Решения, которые нужны от директора

1. **30% — наценка после комиссий, но до налога УСН 15%?**  
   В проекте принято: да, gross-up только на `p` (комиссию); налог УСН 15% уменьшает чистый результат. Если нужно 30% после налога УСН — это отдельная политика.
2. **Единая цена для всех способов оплаты или разная?**  
   В проекте по умолчанию — единая цена; комиссия учитывается консервативно и пересматривается по факту. Дифференцированная цена — только отдельным решением.
3. **Доставка 10 000 ₽ — окончательная цена без НДС?**  
   Подтвердить, что цена фиксированная и не облагается НДС.
4. **Максимальная скидка и кто её согласует?**
5. **Что делать, если `D_internal > 10 000`?**  
   Субсидировать, менять цену, отказывать — нужен регламент.
